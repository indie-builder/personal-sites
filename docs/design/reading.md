# 导航、信息流与详情阅读参考

[设计规范入口](../../DESIGN.md)规定全站 token、布局与通用规则；本文件保留对应场景的完整约束。

### 内容导航

- 桌面内容区头部是刊头而非 tab：当前版块为 Title 档刊名（0.95rem/620/`-0.035em`）居左，兄弟版块为 quiet（`#767676`）`0.78rem` 同行链接居右，hover 与过渡中转墨色；整个头部共享唯一一条 `1px` 细线并保持 sticky。桌面无独立「首页」：`/` 的右侧即每日动态，刊头不再提供「首页」链接。
- 刊头只承载阅读入口（每日动态/每日关注/提示词/设计收藏/抖音收藏/开源关注）。问答只通过个人简介中的像素角色展开，不列入桌面或手机导航。
- 不叠加两排分类 Tab。每日动态、每日关注、提示词与开源关注共用右侧单选筛选菜单；开源关注工具栏左侧显示当前结果的项目数，菜单显示每个主题的全库计数，当前项用勾选与触发器文字表达。工具栏随栏目导航停靠，小屏菜单保持在视口内。
- 窄屏（≤900px）沿用身份区下方的横排移动导航（含首页链接），允许横滑并保持当前项可见。手机导航 0.78rem，当前项加重；触达区域至少 44px。
- 阅读版块各有独立路径（`/ai-news`、`/curation`、`/design`、`/douyin`、`/open-source`），刊头兄弟链接与移动导航都指向完整路径；首页固定展示个人介绍与每日动态。

### 手机头部与日期工具栏

- 阅读列表滚动超过 80px 后，身份头部以 240ms 向上收起，只留下栏目导航；回到顶部 16px 内展开。通过 sticky 停靠偏移保持文档高度，避免反复跳动；首页与 Ask 不应用该收起行为。
- 首页与栏目之间切换保留头像、姓名、GitHub／语雀／作品集／关于我整行的移动过渡。临时覆盖层不可交互，完成或中断后必须清理；离屏身份区不生成无意义的过渡副本。
- 每日动态、每日关注、提示词、设计收藏、抖音收藏共用日期吸顶与跟随规则。日期固定在栏目导航下方，内容滚动到下一日期时更新，沿用各栏目已有的日期格式和排序。
- **日期左、筛选右。** 不把整组推向右侧。手机日期与筛选均用 0.74rem / 500，日期降调为辅助灰；导航比日期略强，内容标题保持阅读主角。
- 每日动态使用站内 Radix 单选菜单，包含全部、精选和已有分类；右侧对齐展开，当前项有勾选。菜单细线边框、黑白灰、无阴影，选项至少 44px 高；不用浏览器原生 select。
- 筛选按钮保留焦点，空结果仍可切回全部。其他三个日期栏目没有分类功能时，只显示日期，不虚构筛选控件。

### 每日关注流

- 这是**判断流**：标题是他的判断式题名，策展解析是正文主角（`0.82rem`、`#3f3f42`），不是次要灰字——整条流读作他的批注，而不是他转发的列表。
- 每日关注按来源拆分：`/curation` 只呈现 X 来源，抖音来源条目由「抖音收藏」（`/douyin`）单独成流；两条流共用同一套剪报簿样张与密度，只是登记栏的来源行分别为 `X · @handle` 与 `抖音 · 作者名`。
- 每条内容是一行登记簿记录，不是卡片：左列是固定宽（`minmax(7rem,8.5rem)`）的 quiet 登记栏（日期、来源与作者、附件逐行，`0.72rem`；附件是从 media/quoteContext 归并的登记词——图片/视频/GIF/引用，有才出现），右列是标题与解析；不使用方向箭头，整行即是链接。
- 剪报簿结构：解析之下随附**来源摘录**——X 条目剥离 t.co 短链，抖音条目采用经审核的转写/OCR 证据摘录；统一折叠空白、两行裁切（`-webkit-line-clamp:2`），`1px` 左引线（`#dededf`）+ 降调灰（`#656568`、`0.78rem`）标记"来源声音"，与解析的主角层级区分；再下一行是 quiet 标签登记行（`0.67rem`、`·` 分隔，纯文本不用徽章）。
- 行与行之间只用 `1px` 分隔线；hover 只让标题转向墨色，禁止增加背景卡、阴影或彩色条。
- 标题、摘要和链接保留真实来源与日期；行密度由上下 `1.5rem` 内边距维持，三条内容流共用同一密度与栏宽。
- 窄屏（≤900px）收敛为单列：登记栏回到标题上方，以 `·` 分隔为一行。

### 提示词

- `/prompts` 是每日关注中提示词内容的独立入口，沿用身份轨、连续登记流、日期栏和主题单选菜单。标签依据实际内容开放增长，菜单统计完整提示词子集，选择标签后先筛选再分页。
- 详情沿用剪报对页：原文保留语言与换行；右页先显示需要时的中文译文并标明机器翻译，再接策展解析。中文来源不重复生成译文。详情标签提供同类内容入口。
- 精选追评与案例接在原帖之后，使用细线分隔的连续条目，显示收录理由、原文、需要时的译文、作者与来源链接；有图片或视频时沿用原帖媒体控件，不创建独立卡片。
- 提示词详情返回与相邻导航均留在提示词集合内，canonical 指向共享的每日关注详情；无译文或无合格追评时省略对应区域，不用摘要或生成内容补空。

### 设计收藏流

- `/design` 是每日关注的高置信设计相关子集，不复制第二份内容；同步阶段以原文、外链与图片/视频代表帧判断相关性，只有 `status=include` 的 X 条目进入公开列表。
- 继续使用判断流的双列登记簿与细线分隔；左列依次登记收录日期、`X · @handle` 与设计子类（多个子类以 `·` 分隔），右列保持题名、摘要、来源摘录和标签的原有层级。
- 有可用 X `videoUrl` 时在右侧正文列内直接显示原生控制条播放器，经 `/api/x-media` 代理播放；播放器与详情标题链接分离，禁止把交互式视频嵌套进整行链接。加载失败在图注内保留 quiet 状态文案与「在 X 上查看原视频」出口；无视频时保持普通判断流，不增加空媒体占位。
- animated GIF 仅在常规动态偏好下自动播放并循环；`prefers-reduced-motion` 下必须关闭两者，保留封面与原生手动播放控件。普通视频不自动播放。
- 空列表只在流尾居中显示 quiet 文案「暂时没有高置信度的设计收藏。」，不增加插画、卡片、行动按钮或空占位骨架。

### 策展详情

- 保持同一身份轨；页面是**摊开的剪报簿对页**（`curation-detail--spread`）：头部通栏（收录日期 quiet 行 → detail headline → 摘要 → 标签 pill 行），不再使用 eyebrow 窄列网格。
- 主体 `curation-detail__body` 为 `minmax(0,2fr) / minmax(0,3fr)` 对页双列：左页是**原推剪报**样张贴片，右页是**深度解析**；两列的 eyebrow 标签同基线对齐，是页面上仅剩的"栏题"语言。
- 左页样张在桌面（≥901px）sticky 钉住（`top:2rem`、`max-height:calc(100dvh - 4rem)`、超高时列内 thin 滚动条滚动），解析滚动时证据始终在视线内；窄屏单列堆叠，顺序为头部 → 剪报 → 解析 → 来源 → 相邻。
- **来源摘录**样张贴片：细线框（`1px var(--line)`、`.75rem` 圆角）把证据"贴"在页面上——片内署名行保留平台、作者与发布日期；X 原文继续展开 t.co 链接、引用与媒体，抖音展示经审核的转写/OCR 摘录；媒体只认 `12px` 圆角与 hover 缩放，不另加阴影。
- 原始来源通栏（eyebrow 在上、细线链接列表）；**相邻剪报**收束阅读：页底双列登记行（上一则·较新收录 / 下一则·较早收录，quiet 标签 + stream headline 题名，第二条右对齐）；单侧存在时"下一则"仍落右列（`data-dir` + `:only-child`），窄屏单列复位；排序与列表完全一致，且相邻导航不跨来源——抖音条目只在抖音条目间翻页，X 条目只在 X 条目间翻页。详情页返回链接同样按来源分流：抖音条目返回「抖音收藏」，X 条目返回「每日关注」。
- Markdown 内容可以有阅读型排版、代码块与表格，但不得回退到旧版工作台/知识库壳层；`open-source` 详情继续复用旧两列骨架，`--spread` 修饰类是两者之间的隔离边界。

### Markdown 正文（全站统一）

- 所有长文 Markdown（策展解析、开源中文阅读版等）只用全局 `.article-markdown` 一套排版：正文 `.92rem`/`1.78`，标题 610/`-0.026em`（h1 `1.4rem` → h4 `.92rem`），代码块深色底、表格 `.82rem`。
- 问答等对话场景的 Markdown 可以用更密的正文（body 范围内），但标题字重/字距与 `.article-markdown` 同档。
- 新增 Markdown 场景不得再建第三套排版；模块级 Markdown 样式一律视为 drift。

### 每日动态流

- 这是**跟踪流**：新闻题名保持主角，摘要为 quiet 文摘——与判断流（每日关注、开源关注）的层级差异是有意的，判断流读他的文字，跟踪流读事件本身。
- 与每日关注流同构：按日分组（桌面日期用 Title 档，手机日期按辅助工具栏档；星期/条数为 quiet），条目是 1px 分隔线的连续流，不做时间轴轨道、圆点或卡片。
- 条目结构与每日关注流同为登记簿：左列登记栏为时刻、出处（列表只显示出处名，@handle 留在详情页）、分类（「精选」只是登记栏里的一行 quiet 文本，不做徽章），右列 stream headline 标题与摘要；无方向箭头，不展示上游评分。
- 窄屏元信息以 `·` 分隔为一行，分隔点尾随在前一项之后，折行时行首不出现孤点。
- 滚动分页加载，追加条目以 `isAppended` 标记播放 0.45rem 上浮 + 32ms 阶梯的渐入；分类筛选切换时整列重挂载，过滤后前 8 行重播同一阶梯（`FILTER_REVEAL_COUNT`），分类当前态由菜单勾选与触发器文字表达，不再使用滑动指示线；空态、加载骨架、失败重试齐备。

### 每日动态详情

- 与策展详情共用身份轨与桌面滚动容器；顶栏只有返回链接。
- 结构：kicker（分类 · 精选，quiet 文本）→ detail headline 级 h1 → 元信息 → 导读 → 推荐理由（仅精选条目有数据，左侧 1px 引线）→ 实心 pill 原文出口（external-link 组件）+ quiet 域名。

### 开源关注流

- 与每日关注流同为**判断流**：左列登记栏为主题分类与状态（持续跟踪/已提炼/计划试用等），右列为仓库名（stream headline 档）、他的中文判读（正文主角，`0.82rem`、`#3f3f42`），以及一行 quiet 索引文本（维度 · 类型，以 `·` 分隔）。
- 不使用带边框的 tag 徽章，不使用方向箭头；行分隔线、hover 行为与窄屏收敛与另两条流一致。
- 详情页与每日动态详情同构：返回 → 仓库名 h1 → 判读（`personalNote`，判断流正文主角档 `0.82rem`、`#3f3f42`）→ 仓库文档 tabs → 实心 pill「在 GitHub 查看仓库」+ quiet 域名。判读必须在详情页出现，不能只在列表里当钩子；GitHub 出口必须有，访客读完判读的最高点不能没有顺势出口。
